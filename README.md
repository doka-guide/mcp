# MCP-сервер Доки

Даёт редактору кода и ИИ-помощнику доступ к [Доке](https://doka.guide) —
открытой энциклопедии по веб-разработке на русском языке. Помощник ищет
материал и читает его целиком в markdown, вместе с датой обновления, данными
о поддержке браузерами и авторами.

Зачем: модель отвечает про веб-платформу по-английски и по памяти. С этим
сервером она отвечает по Доке, по-русски и со ссылкой на материал.

## Что умеет

- `search_doka` — поиск по 1000 материалов шести разделов: CSS, HTML,
  JavaScript, доступность, инструменты веб-платформы, рецепты. Отдаёт
  заголовки, пути и краткие описания.
- `read_doka` — материал целиком в markdown. В шапке: `url`, `updatedAt`,
  `baseline` (поддержка браузерами по данным web-features), `authors`,
  `license`.

Сервер ничего не хранит и никуда не пишет: только читает публичные адреса
`doka.guide`. Индекс разделов держится в памяти час.

## Установка

Нужен Node 20 или новее.

### Claude Code

```bash
claude mcp add doka -- npx -y @doka-guide/mcp
```

### Cursor, Windsurf, VS Code

Добавьте в файл настроек MCP:

```json
{
  "mcpServers": {
    "doka": {
      "command": "npx",
      "args": ["-y", "@doka-guide/mcp"]
    }
  }
}
```

## Как спрашивать

Помощник вызывает сервер сам, когда вопрос про веб-платформу. Можно и прямо:

- «Посмотри в Доке, что такое `overflow-wrap`»
- «Как в Доке объясняют доступность кнопок»
- «Прочитай материал Доки про `fetch()` и напиши пример с отменой запроса»

## Чего сервер не делает

- Не ищет по полному тексту материалов: корпус поиска — заголовки, описания
  и раздел «Кратко». Точные названия свойств и методов находятся хорошо,
  разговорные вопросы — хуже, поэтому сервер отдаёт до 20 кандидатов
  с описаниями, а выбирает модель.
- Не отдаёт демки: их надо открывать в браузере, по адресу вида
  `https://doka.guide/css/<материал>/demos/<имя>/`.
- Не пишет в репозиторий Доки и не умеет предлагать правки.
